# Rotash — MVP 試作

友達と一定期間をかけて、**1つの写真作品を完成させる**アプリの試作です。
App Store 公開版ではなく、実際に友人と使って体験価値を検証するためのものです。

---

## 体験の中心

Rotash は「自分の担当日に写真を投稿するアプリ」ではありません。

> 参加者全員が同じ7分割キャンバスを毎日見ながら、
> 1週間かけて1つの写真作品を完成させるアプリ

- **撮れるのは1日に1人だけ**（全員が毎日投稿するのではない）
- **見るのは誰でも、いつでも全部**。曜日による閲覧制限は一切ない
  - 金曜担当者も、月〜木の写真をずっと見られる
  - 土曜担当者も、それまで完成した写真を見られる
- 3人なら 月A 火B 水C 木A 金B 土C 日A と一巡し続ける
- 7枚そろうと、その週の作品が完成する
- 端末を**横向き**にすると、7分割された「今週の作品」が現れる

全員が「観客」と「制作者」の両方になります。自分の担当日だけ作者になる。
「自分の番だから開く」だけでなく、「今日はどこまで完成したかな」で毎日開く体験を狙っています。

縦向きは Rotash の入口。表示するのは グループ名 / 招待コード / 今日の担当者 / Memories / 設定 だけです。
横にした瞬間に「THIS WEEK」を見せたいので、**縦では今週の7分割は一切出しません**
（進捗バー的な埋まり具合表示も含めて）。完成した過去作品のプレビューだけは Memories に出ます。

---

## 動かし方

1. Xcode 16 以降で `Rotash.xcodeproj` を開く
2. `Rotash` ターゲットの Signing で自分の Team を選ぶ
   （`PRODUCT_BUNDLE_IDENTIFIER` は `com.rotash.mvp`。必要なら変更）
3. 実機を選んで Run（**カメラを使うので実機推奨**）

> `Rotash/` 配下は Xcode 16 のファイルシステム同期グループです。
> ファイルを増やしてもプロジェクトファイルを触る必要はありません。
> 古い Xcode で開けない場合は `xcodegen generate`（`project.yml` 同梱）でも生成できます。

シミュレータではカメラが無いため、シャッターを押すとダミー画像が入ります。
7分割が埋まっていく流れだけは確認できます。

## 撮影のつくり

**通常のカメラプレビューは出しません。**

- 画面には最初から 7分割レイアウトがある（他の枠の写真もそのまま見えている）
- ライブビューは**自分の担当枠の中だけ**に出る
- そのため、撮る人はこれから撮る1枚の完成イメージを見ないまま撮ることになる
- 撮ると、その枠がそのまま写真で埋まる（確認画面なし）

操作は 2通りとも使えます。

- 担当枠をタップ（1回目で選択 / 2回目で撮影）
- 画面下中央の固定シャッター

**撮影権限**: その日の担当者だけが、その日の枠を撮影できる。
他の日の枠は見えるだけで撮れない（未来の枠も、他人の日も）。

**自撮り**: シャッターの左に出る `FLIP` で前面 / 背面カメラを切り替えられます
（`Services/CameraController.swift` の `switchCamera()`）。
7分割の枠は横に狭く、隅に小さなボタンを置くと押しづらいので、
シャッターと同じ列に 44pt 以上のタップ領域で置いています。

**撮り直し**: 現状は仮で **無効**（一度撮ると確定、上書きはできない）。
撮影回数の表示・フィルター・編集・AI加工もありません。
ただし判断が変わりやすい部分だと分かっているので、
`App/FeatureFlags.swift` の `RotashFeatureFlags.allowRetake` を `true` にするだけで、
撮り直し UI（撮影済みの担当枠をタップ→ライブビューに切替→ボタン上に SHOOT / RETAKE
と表示→もう一度撮ると上書き）がコードの変更なしで復活する構成にしてあります。
撮影可否の判定を `AppViewModel.canShoot` の1箇所に集約しているのはそのためです。

写真は横長のまま保存します。縦への自動変換はしません。

**画面の見た目**: 7分割は常に同じ比率の7列です（`GeometryReader` で幅を明示計算）。
最初の1枚だけ大きく見える、というレイアウトにはしていません。
右上の「N / 7」のような進捗表示、写真上の「TODAY」表記、撮影中の「◯枚そろいました」
といったテキストは削っています。7枚が左から埋まっていく状態そのものと、
各枠に出ている曜日・担当者名だけで十分伝わる、という考え方です。

## 共有

加工・テンプレート・装飾は入れていません。

- **7枚の写真そのもの**を書き出す（Instagram カルーセル用）
- **7分割のまま1枚**にしたコンタクトシート（アプリ内の見え方と同じ）

## サーバーを持たないので「バトン」はファイルで渡す

Firebase もアカウントも使わない指定なので、保存は端末ローカルのみです。
そのままだと友達と同じ作品を育てられないため、**バトンの受け渡し**だけ用意しました。
縦画面を Rotash の入口として最小限にする方針に合わせて、バトンの導線は
ホーム画面ではなく **設定画面の中** に置いています。

- 設定 → 「渡す」→ `.rotash` ファイルを AirDrop / LINE などで送る
- 受け取った人は 設定 → 「受け取る」から読み込む（AirDrop から直接開くのも可）
- 中身は「グループ情報 + 今週の7枠 + その写真」だけ
- 同じ週を別々に撮っていても、写真は消えずに合流します

過去作品（Memories）は各自の端末にたまります。
その週の最後のバトンを受け取った人の端末に、完成した作品が残ります。

**検証の進め方（おすすめ）**
- まず 1台を回す形でも体験は成立します（7分割が埋まる感覚の確認）
- 2台以上なら、撮ったらバトンを次の当番に送る運用で「待つ楽しさ」まで確認できます

> **既知の制約**: 「見るのは誰でもいつでも全部」は同じ端末内では完全に成立しますが、
> 端末をまたぐ同期は今のところバトンを渡すタイミングでしか起きません。
> つまり「毎日開いて友達の写真を見る」を複数端末で厳密に検証したい場合、
> 撮った直後にバトンを渡す運用にしないと他のメンバーの端末には反映されません。
> ここは MVP の一番弱いところなので、体験が刺されば次はサーバー同期（Firebase 等）に
> 差し替える前提で `RotashStore` を protocol にしてあります。

## 週の扱い

グループは毎週続きます。「新しい週を作る」操作はありません。

- カレンダー上の週は常に **月曜〜日曜**
- 月曜になったら自動的に次の週へ切り替わり、前の週はそのまま Memories へ
- THIS WEEK には常に今の週だけを表示

**週の途中で始めた場合**、その日から日曜までが初回の作品になります。
金曜に作れば FRI/SAT/SUN の 3 枚、水曜なら 5 枚。
翌月曜からは通常の 7 枚に戻ります。
「作った曜日が毎週の開始曜日になる」わけではなく、初回だけの特殊ケースです。

## 担当者の決め方

`Services/AssignmentPlanner.swift`。完全ランダムでも単純ローテーションでもなく、
**公平性を保証した上でランダム**に決めます。副作用の無い純粋ロジックです。

優先順位:

1. 累計担当回数の公平性
2. その週の担当回数をできるだけ均等に（2人=4/3、3人=3/2/2、4人=2/2/2/1 …）
3. 同じ人の 2 日連続を原則避ける
4. 前週とまったく同じ並びを避ける
5. 残った候補からランダム

条件を全部は満たせない場合（1人グループなど）でも、進行不能にならないよう
段階的に条件を緩めて必ず割り当てます。

## 担当者はその日まで公開しない

週の頭に全員分の担当を公開しません。**今日までの担当者だけ**が見えます。

- 過去の曜日: 写真 + 担当者名
- 今日: 担当者名 + 撮影状態
- 未来: 空白のみ（写真も担当者名も出さない）

「次に誰が撮るのか分からない」という不確実さ自体を体験として残すためで、
カレンダーやスケジュール表にはしません。

## 途中参加

新しいメンバーが週の途中で入っても、「翌週まで閲覧だけ」にはしません。
**その週から作品づくりに参加**します。

未来の担当者はそもそも誰にも公開していないので、内部で組み替えても
「予定が変更された」という見え方になりません。この性質を使っています。

- 過去の枠・今日の枠は **絶対に変更しない**（写真も担当者も）
- 変更するのは「今日より後の、まだ公開していない枠」だけ
- 途中参加した人には、参加後の **最初の枠を優先して** 割り当てる
  （木曜参加なら原則そのまま金曜担当）
- 残りの日は、その人を含めた全員で通常の公平性ルールに従って再配置
- 翌月曜からは、他のメンバーとまったく同じ条件でローテーションに入る

ユーザーから見ると、金曜になって初めて「今日は D なんだ」と分かるだけで、
内部で再計算されたことは一切表示されません。

## No Shot（写真がなかった日）

担当者がその日に撮らなかった場合、**担当を変更したり代理を立てたりはしません**。
その日は「写真がなかった日」として作品にそのまま残ります。

- assignment は変更しない。その週の残りの担当もそのまま
- 「休み」「欠席」「代理」といった管理アプリ的な表現はしない
- 表示は `—` だけ。写真がないこと自体をエラー扱いしない

枠の状態（写真 / No Shot / 今日 / これから）は保存せず、
**写真の有無と日付から導出**しています（`RotashWeek.state(of:)`）。
状態遷移の処理を持たずに済み、過去の週でも常に正しくなるためです。

### 7枚そろわなくても作品は成立する

`isComplete`（全部写真）とは別に `isFinished`（全枠が決着 = 写真か No Shot）を用意し、
**共有できるかどうかは `isFinished` で判断**します。
`— 📷 📷 📷 📷 📷 📷` のような作品も、そのまま Share / Memories で扱えます。
コンタクトシートでは No Shot の日はその位置が黒いまま残ります。

## 撮影できる条件

- 撮れるのは **自分の当番日の当日だけ**
  （未来は撮れない。過ぎた日も No Shot として確定するので後から埋められない）
- 設定の **自由撮影モード** を ON にすると、当番に関係なく空き枠を撮れます
  （体験を短時間で試すための検証用スイッチ）

過ぎた日を後から撮れるようにしたい場合は、
`App/FeatureFlags.swift` の `allowCatchUpShooting` を `true` にしてください。

## 構成

```
Rotash/
  App/          RotashApp.swift
                FeatureFlags.swift          … 仮仕様の切り替えフラグ（撮り直し等）
  Models/       RotashModels.swift          … Member / Slot / RotashWeek / RotashGroup
  Services/     RotashStore.swift           … 保存層（protocol + ローカルJSON実装）
                PhotoStore.swift            … 写真の実体・サムネイル
                CameraController.swift      … AVFoundation（前面/背面切替対応）
                InviteCode.swift
                WorkExporter.swift          … 共有
                BatonTransfer.swift         … .rotash の書き出し / 読み込み
  ViewModels/   AppViewModel.swift          … 当番判定・撮影・週送り・合流
  Views/        RootView.swift              … 縦横で体験を分ける
                Portrait/ …                 … 入口（作成/参加/招待/今日の担当/Memories）・設定
                Landscape/ …                … THIS WEEK（7分割そのもの）
                Components/ …
  Design/       Theme.swift
Supporting/     Info.plist
```

MVVM。保存層は `RotashStore` protocol 越しなので、
あとから Firebase / 自前API の実装に差し替えれば、そのまま同期版にできます。

## この試作で見たいこと

- 友達の写真が増えていく途中を見るのは楽しいか
- 自分の担当日以外でもアプリを開くか
- 完成まで待ちたいと思うか
- 完成した7枚を Instagram で共有したいと思うか
- 友達を招待したくなるか

機能追加ではなく、「未完成作品を共同制作する体験」の検証を最優先にしています。
