## 3. 新しく採用するものの中身

### 3-1. 「今日の1枚」ウィジェット

Locket 資料 §1 は「今日の担当者名を常時出すウィジェット」を DON'T にした。理由は、朝の「今、初めて知った」と、横にした瞬間に7分割が現れる儀式を壊すから。
**この2つを壊さない形に絞れば、理由は当たらない。**

| 出すもの | 出さないもの |
|---|---|
| その日に撮られた**1枚**（撮られた後だけ） | 今日の担当者名（撮られる前） |
| 撮ったのは誰か（その日は既に公開済み） | 7分割・今週の進捗・「あと◯枚」（F-3 で禁止） |
| まだ撮られていなければ、何も出さないか、静かな空き | 未来の担当者 |

- `IMPLEMENTATION_PLAN` の3つの質問に通す：①今日の担当を当日より前に教えるか → いいえ ②写真を評価の対象にするか → いいえ ③作品の完成に要るか → 直接は要らないが、既に SHOULD の「◯◯が撮った」通知（S2）と同じ役で、**PRODUCT_PHILOSOPHY 4 の最大の未解決問題「今日は誰？」→「何を撮った？」の接続**そのもの
- **サーバー不要で作れる**：ウィジェットは自分で Firestore を読みに行ける（1日40〜70回程度の更新枠）。即時ではないが「今日の1枚」には十分
- タップで開いた先は横にする前の画面。**7分割はアプリの中で、横にして見る**のは変わらない
- 作る量：Widget Extension のターゲット追加、App Group での共有、写真の縮小版。数日
- **いつ**：#28 の後。#28 は「入口の手応え」、これは「コア体験につながるもの」の第一候補（#28 の進め方の3）

### 3-2. 参加直後の流れ（L5 の繰り上げ）

参加した直後に、**今週ここまでの作品を出し、横にするきっかけを動きで見せる**。
#28（自撮り → アイコン）と合わせて「顔を撮る → 今週の中に自分の場所が見える」の1本の流れにする。
作成した直後（まだ写真が0枚）だけは、ふつうの1週間の見本を短く見せる。

### 3-3. App Store 公開前の必須対応

| 項目 | 今 | やること |
|---|---|---|
| 通報（ガイドライン 1.2） | なし | 写真を長押し → 通報。届いた通報に応える連絡先 |
| ブロック（1.2） | なし | グループ内で特定の人の写真を見えなくする（少なくとも自分の画面で） |
| 事前フィルタ（1.2） | なし | 友達だけの非公開グループでも免除の記述はない。何で満たすかは要調査 |
| 連絡先の公開（1.2） | なし | サポート用のメールかページ |
| データ削除（5.1.1(v)） | 抜けると**この端末の写真だけ消える**。サーバー（Firestore・Cloudinary）の写真は残る | 抜けるときに**自分が撮った写真をサーバーからも消す**選択肢 |
| 年齢区分の回答 | 未回答 | UGC：はい、メッセージ：はい、**Social Media：いいえ**（フィードで拡散しないため）。正直に答えられる設計を守る |
| プライバシーポリシー・App Privacy | なし | ANALYTICS_SETUP 5章の通り |

### 3-4. 未インストールの人にも届く招待

今は `rotash://join/CODE`（独自スキーム）。アプリが入っていない人には何も起きない。
Firebase Dynamic Links は終了済みなので、外部サービスを使わない自前の形にする。

1. 招待リンクを `https://（Firebase Hosting の無料ドメイン）/j/CODE` にする（Universal Links）
2. アプリが入っていれば、そのまま参加画面へ
3. 入っていなければ Web ページに作品の画像と**大きな招待コード**、App Store（今は TestFlight）へのボタン。押すとコードがコピーされる
4. インストール後の初回起動で「コピーした招待コードで参加する」を出す（貼り付けボタン。勝手には読まない）

`?from=` を付ければ、GTM が測りたかった K（作品ひとつから生まれたグループ数）も、招待経由の分は測れるようになる。#23（招待の後回し）にも効く。

## 4. 競合の更新（既存資料に無かったもの）

| | 単位 | 撮る人 | 出てくるもの | Rotash との違い |

| **Retro** | 友達（個人の週） | **全員が自分の写真** | 友達1人ずつの「今週」 | Retro は**各自の週の日記**。Rotash は**全員で1つの作品**を、1日1人で作る |
| **Setlog** | 2〜12人のルーム | 全員が毎時 | 1日分の自動動画 | Setlog は「全員・毎時・同時」。**「共有疲れ」の批判**がある。Rotash は1人1日で負担が小さい |
| **BeReal** | 友達 | 全員が同時に | その瞬間 | 日本は BeReal の主要市場（MAU 650万超）。**友達だけの写真アプリを受け入れる土台は日本にある** |

| **TapNow**（日本） | 友達 | 誰でも | ウィジェット | 日本発、200万DL超。ウィジェットの写真共有は既に日本で埋まりつつある → ウィジェットを**主役**にすると負ける。Rotash のウィジェットは作品への入口に留める |

**一言での差別化**：「みんなが毎日撮る」アプリが増えて疲れが出ている中で、Rotash は**「1日1人だけが撮る。7日で1枚になる」**。
Setlog の「共有疲れ」批判は、Rotash の位置取り（負担の小ささ）の追い風になりうる。韓国語ローカライズが既にあるのも、Setlog が当たった市場と重なる。
