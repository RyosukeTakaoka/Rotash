## NEVER — 入れてはいけない

**「便利だから」「みんなやっているから」で入りやすいものを、コードの言葉で書いておく。**

### 既存の実装で守るべきもの（変更禁止）

| 守るもの | 場所 | 壊すとどうなるか |
|---|---|---|
| **未来の担当者を公開しない** | `AppViewModel.revealedAssignee` | Rotash 最大の資産（不確実性）が消え、**当番表アプリになる** |
| **ライブビューを担当枠の中だけに出す** | `ThisWeekView.liveContent` | **カメラを全画面にしてはいけない。** 撮る人が前の6日分を横に並べたまま構図を決める構造が壊れる。「前日の写真に返す」連鎖はこの1点で成立している |
| **週の自動送り** | `AppViewModel.rollWeekIfNeeded()` | 確認ダイアログや「次の週を作る」ボタンを足さない。**継続をオプトインにした瞬間に継続率が落ちる**（7人全員の Yes が要る → 0.9⁷ = 48%） |
| **過去日を後から撮れない** | `FeatureFlags.allowCatchUpShooting = false` | **true にしない。** 待ち時間の価値がゼロになる |
| **No Shot を失敗として演出しない** | `RotashWeek.state(of:)` / 表示は `—` のみ | 「休み」「欠席」「未提出」の表現を足さない。**穴が残る事実だけで十分に効いている** |
| **担当者決定ロジック** | `Services/AssignmentPlanner.swift` | 公平性・連続回避・前週回避は既に正しい。**触らない** |

### 追加してはいけない機能

| 機能 | なぜ |
|---|---|
| **連続週数（streak）** | 7人依存で毎週約30%壊れる。壊れたとき「お前のせいで切れた」が発生し、**共同制作が相互監視に変わる** |
| **「Next Rotash」ボタン** | 既に正しく解けている問題（自動週送り）に悪い解を上書きする |
| **タイムライン / 他グループの作品を見る画面** | 「自分たちの1週間」が「他人のコンテンツ」に置き換わる |
| **いいね / リアクション / スタンプ** | 作品が外部評価の対象になった瞬間、**日常が撮れなくなる。** BeReal が壊れた道筋そのもの |
| **コメント欄** | LINE で既にやっている。Rotash が持つ理由がゼロ。**タイトルを全員が書ける形にするのもこれに該当する** |
| **フォロワー / 複雑なプロフィール** | Rotash の単位は「7人のグループ」であって「個人と観客」ではない |
| **撮影率・貢献度・サボり検知** | 相互監視 |
| **個人フィード / 自分の写真だけのアルバム** | 「7分割が親、個別写真が子」の関係が反転する |
| **催促通知の複数回送信** | 義務化の入口。**通知は1日最大2通**（朝の担当 + 撮られた）を超えない |
| **撮り直し無制限** | 「その日の1枚」が「その日のベストショット」になる |
| **グループ横断のネットワーク効果** | **Rotash は Network Effect を意図的に7人で打ち止めにする。** 超えた分は価値ではなくノイズ |
| **シェアへの報酬（ポイント・特典）** | シェアが作業になり、シェア画像が広告として受け取られる |
| **定型キャプションの自動挿入** | 「Rotash で作りました！#Rotash」は広告に見える。投稿者が恥ずかしい。**キャプションは空にする** |
| **7人集まるまで開始できないゲート** | 7は下限ではなく**定員**。ゲートはグループを永久に始まらせない |
| **ランキング / ポイント / ガチャ / バッジ / テーマシステム** | 作品が報酬でなくなる。Memories という唯一の蓄積が薄まる |

### 判定に迷ったときの3つの質問

1. その機能は **「今日は誰？」の答えを、当日より前に教えるか？** → Yes なら入れない
2. その機能は **写真1枚を「誰かに評価されるもの」にするか？** → Yes なら入れない
3. その機能を使わないと、**作品が完成しないか？** → No なら、たぶん要らない
