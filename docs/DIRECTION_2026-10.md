# 方針メモ：「1日1回」に価値を持たせる（2026-10-16）

オーナーが決めた、これからの考え方の向き。**まだ何も作らない。** 日曜（10/18）の聞き取りと、もう1グループでのテストの結果を見てから、具体的な形を決める。
背景の調査は [`reports/Rotash 改善のための事例調査.md`](../reports/Rotash%20改善のための事例調査.md)。

## 1. ユーザーが感じた問題（友達テストより）

| # | 問題 | 中身 | 本当の原因の見立て |
|---|---|---|---|
| 1 | 機能の勘違い | 「みんなで1枚の絵を作る」と思っていた。完成イメージを見せたら伝わった | **伝え方の問題**。完成作品が無い最初のテスターには、見本が無かった |
| 2 | 1日1回しか開かないから飽きそう | 「主にそれ」と本人も言った。まだ飽きてはいない（予想の声） | 回数そのものより、**開いても反応や更新が無い**ことが本質だろう（要確認） |

「1人で7枚撮ってみんなで見る」「撮り直しの時間制限は要らない（送信したら撮り直せない）」は、問題ではなく**友達が出した解決策**として分けて扱う。

### 誘ったけれど始めなかった人の声

- **本物のシェア画像（月〜金の5枚）を見せたうえで** **「それ Setlog やん」**。やらない理由は「セットログでいいから」「（友達の写真が見れるのは）同じやん」。BeReal は使っていない。部活の Setlog に誘われて入り、今ハマっている
- 読み取れること:
  - **第一印象が Setlog のまねになっている**（説明の段階で Rotash だけの部分が伝わっていない。問題1の伝え方と同じ根っこ）
  - 「仲間と毎日撮って思い出にする」用事は、すでに Setlog に任せてある。乗り換えてもらうには、今のアプリへの不満か、新しいアプリの強い魅力が要る（調査レポートの「4つの力」）
  - 外から一番目立つ「横にするとカメラ」は Setlog を参考にした部分なので、そこから説明が始まると似て見えやすい
- Setlog との違い（ここを打ち出す）: 撮るのは**1日に1人だけ**（次は誰か分からない）／1枚の写真（表と裏）／**7枚で1週間の作品**／**1日1回の静かなアプリ**。最後の点は、この方針（柱 B）とそのまま重なる
- シェア画像は「知らない人が最初に Rotash と出会う場所」なので、**画像そのものが違いを伝えられていない可能性**がある。どこを見て Setlog だと思ったか（縦に細長い見た目／顔の丸が並ぶところ／「みんなで毎日撮る」という説明）で、直すところが変わる
- **分かったこと（2026-10-16 追記）**: 見た目ではなく**中身（友達の写真が見られる）が同じ**と感じていた
  - 「友達の写真を見る」アプリとして比べると、撮る量の多い Setlog に勝てない（本当に下位互換になる）。**「1日1回」を売りにするだけでは「少ない Setlog」に見える**。Setlog に無い価値（次は誰が撮るか分からない／7枚で1週間の作品／毎週の作品が積み重なる）がセットで伝わる必要がある
  - 今のシェア画像は「友達の写真の一覧」に見えていて、Rotash だけの特別さ（1日1人が順番に撮った・1週間で1つの作品）が読み取れなかった。いつか直す価値がある
  - Setlog にハマって満足している人は、乗り換えてもらうのがいちばん難しい。狙う相手は、Setlog を使っていないグループや、違う楽しみを求める人かもしれない
  - 聞き方の反省: 「友達の写真が見れるのが下位互換ってこと？」はこちらから答えを渡す聞き方だった（本人は乗っただけかもしれない）。次は「どこが同じだと思った？」のように答えを渡さずに聞く／完成した Rotash の作品を見せて「これでも Setlog と同じに見える？」／Setlog と別にもう1つ入るなら、どんなものか

### オーナー自身へのアンケート（2026-10-17、テスト6日目の朝）

オーナーは BeReal も Setlog もほぼ使っていない。6日目の時点で、最初に比べて飽き始めている。それでも、自分も含めてもっとワクワクするアプリにしたい。

| 聞いたこと | 答え |
|---|---|
| 自分の番ではない日に開いた回数 | 1日に2〜3回。撮った人が投稿したあとも、過去の写真まで見たくて開いた。ただ最近は減っている |
| 最後に開いたとき、したこと | 横にして7分割を見た／新しい写真がまだ無かった／裏返しや全画面で見た |
| 飽き始めたきっかけ | 毎日同じに感じた。最初の番が火曜で、**水・木・金・土と4日間、撮る番が無かった** |
| いちばんワクワクした瞬間 | 友達の写真が届いたとき／作品が埋まっていくのを見たとき。いちばんワクワクしそうなのは、**日曜に完成して Instagram のストーリーで他の人から反応が来ること** |
| 友達の写真を見たあと | 開発者として LINE で「ありがとう」と送った。文やリアクションで返したいかもしれない |
| 自分が撮ったあと | 作品に入って満足した。今日は友達と遊ぶので、**それを撮りたいからもう一度撮りたい**と思った（日があいたせいかもしれない） |
| 番の間隔 | 均等でなくてもいいが、3日に1回くらい |
| 明日使えなくなったら | 少し残念 |

読み取れること:

- 最初は開く理由があった（1日2〜3回）。問題は「最初から理由が無い」より、**物珍しさが薄れたあとに新しく開く理由が増えない**こと
- **番が4日空いた**。今の担当の決め方は「2日続けて同じ人にしない」だけで、「間を空けすぎない」条件が無い。**ルールを緩めずに直せる**（番の間の上限を足す）。最初に試す候補
- 撮りたい気持ちは、出来事がある日に生まれる。番がランダムなこととの食い違い（すぐには変えない。強制力に関わる）
- **反応を LINE で返していた**＝ユーザーが自分で抜け道を作っている。アプリの中で一言・スタンプを返せれば、見る側の「やること」と撮る側の「見てもらえた」が同時に生まれる（柱 A の両方に効く）
- 開いても新しい写真が無い「空振り」がある（柱 B の「1回の濃さ」）
- 週の山場は「完成して外の人から反応が来ること」。日曜の完成と共有を、週でいちばん大きな出来事にする方向と合う
- 「少し残念」＝オーナー自身にとっても、まだ「なくてはならない」になっていない。「とても残念」にするのが目標

## 2. オーナーの考え

- オーナー自身は「1日に何度も開く必要はない。1日1回開いて、それが1年続くほうが嬉しい」と考えていた。友達の意見は、その好みと利用者の需要がずれていたことから出たものだと受け止めた
- そこで **「開く回数を増やす」のではなく、「1日1回開くことに価値を持たせる」** 方向に考えを向ける
- これがうまくいけば、何度も開かせる他のアプリとの**差別化**になり、Rotash らしさを残した**アイデンティティ**になる

## 3. 考え方の柱

### 柱 A：撮る側と見る側を、別の問題として考える

| | 撮る側（その日の担当） | 見る側（担当でない人） |
|---|---|---|
| どれくらいあるか | 1人あたり週に1〜2日 | 1人あたり週に5〜6日（こちらが大部分） |
| 困っていること | 撮ったら終わり。反応が返ってこない（見られたかも分からない） | 開いても新しい写真が1枚あるだけ。自分にできることが無い |
| 測る数字 | 担当日に撮った割合 | 担当でない日に開いた割合 |

見る側の小さな行動（たとえばワンタップの反応）は、そのまま撮る側への反応になる。1つの手で両方に効く可能性がある。ただし分析は分けておく。

### 柱 B：1日1回を価値にする（「回数」ではなく「1回の濃さ」）

問いを「どう回数を増やすか」から「1回開いたときの中身をどう濃くするか」に変える（エレベーターの鏡と同じ発想）。

- 成功例: **Wordle** はわざと1日1問。1回が楽しく、全員が同じ日に同じことをして、結果を見せ合える
- 注意: **BeReal** は1日1回の通知だけでは、物珍しさが消えたあとに中身が薄く感じられて大きく減った

材料の候補（**まだ作らない**。テストの結果を見て選ぶ）:

- みんな同じ時刻に公開する（今の「◯◯が撮った」をすぐ届ける通知とぶつかるので、どちらを取るか決める必要あり）
- 10秒で終わる決まった流れ（見る → 裏返す → ワンタップで反応 → 「あと◯枚で完成」 → 閉じる）
- 日曜の完成を週の山場にする
- 伝え方：「1日1回、10秒。SNS疲れしない友達アプリ」のように、回数の少なさを売りにする

気をつけること: 今のテスターは Setlog・BeReal を使っていて「もっとやることが欲しい」側の人たち。この方向が刺さる相手かどうかは、まだ分からない。
