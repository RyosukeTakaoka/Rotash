## 0. 準備

Mac のターミナルで、リポジトリの一番上のフォルダ（`firebase.json` があるところ）に移動してから:

```sh
git pull                       # まずこのブランチの最新を取ってくる
npm install -g firebase-tools  # Firebase のコマンド（初回だけ）
firebase login                 # ブラウザが開くので、Firebase のアカウントでログイン
firebase use rotash-f83a4      # 対象のプロジェクト（.firebaserc にも書いてある）
```

そのあと Xcode で一度ビルドし、**⌘U でテストを流す**（`RotashTests`）。
この変更はコンパイラの無い環境で書いたので、最初のビルドで型の食い違いが出るかもしれない。
出たらエラー文をそのまま貼ってもらえれば直す。

## 1. 匿名ログインを有効にする

Firebase コンソール → **Authentication** → 「始める」→ **Sign-in method** → **匿名** → 有効にする → 保存。

- 利用者には何も見えない（登録画面もパスワードも無い）。裏で「この端末の利用者」が1つ作られるだけ。
- これで、アプリを入れ直しても同じグループに「前の自分」として戻れるようになる（同じ名前の別人が増えない）。
- 有効にしていなくても、アプリは今までどおり動く（ログインに失敗したら、トークン無しで送る）。

## 2. セキュリティルールを反映する

**先に、今のルールを控えておく。** コンソール → Firestore Database → **ルール** の中身を、どこかにコピーしておく
（反映すると上書きされるため。何かあったら貼り戻せば元に戻る）。

```sh
firebase deploy --only firestore:rules
```

入るルール（`firestore.rules`）の中身:

- グループ（`rotash/招待コード`）: 招待コードを知っている人だけ読める。**一覧（全部のグループを読む）は誰にもできない**。消すこともできない。書けるのは決まった形（`payload` と `updatedAt` だけ）のときだけ。
- 報告（`reports`）: 書くだけ。読むのはオーナーがコンソールで。
- 端末（`devices/uid`）: 押し出し通知の宛先。本人が自分の分だけ書ける。

`allowsLegacyClients()` が `true` のあいだは、ログインしていない古い版のアプリも読み書きできる（5 で閉じる）。

反映したら、手元の iPhone でアプリを開いて、写真が見える・撮れることを確かめる。

## 3. App Store に公開したとき（招待のリンク）

自前の招待ページは持たない（置いておく負担が重いので、2026-10-15 にやめた）。
そのかわり、**App Store に公開されると、招待の文章に App Store のリンクが自動で付く**（`AppStoreLink`）。

- アプリを開いたときに、Apple の検索（iTunes Search API。無料・登録不要）で Rotash が App Store にあるかを確かめる。
  公開前は見つからないので、これまでどおり「招待コード」だけの文章になる。
- 公開後に届く文章: 「Rotash で一緒に写真を撮ろう。／招待コード ABC234／アプリ: https://apps.apple.com/…」
- 受け取った人は、リンクからアプリを入れ、**招待の文章をまるごとコピーして、参加画面の「貼り付け」**を押せばコードが入る
  （文章の中からコードだけを拾う）。手で6文字を打ってもよい。
- アプリが入っている人には、これまでどおり `rotash://join/コード` のリンクも添える。

URL を書き換えてアプリを出し直す必要はない。公開した日のうちに、招待する側がアプリを開けば次の招待から付く。

## 4. 「◯◯が撮った」の押し出し通知（保留）

今日の担当が撮ったら、ほかのメンバーに「◯◯が今日の1枚を撮りました」を届ける仕組み。
Firebase の Cloud Functions（`functions/`）で作ったが、**Cloud Functions は従量課金（Blaze）でないと動かせない**ので使わない（2026-10-15、オーナー判断）。
無料の代わりの方法を選んでいるところ（[`PENDING_DECISIONS.md`](PENDING_DECISIONS.md)）。決まるまで、この通知は届かない（ほかは全部動く）。

どの方法でも共通して要る準備（無料）:

1. **APNs キーを作る**: [Apple Developer](https://developer.apple.com/account/resources/authkeys/list) → Keys → ＋ →
   「Apple Push Notifications service (APNs)」にチェック → 作成 → `.p8` ファイルをダウンロード（**1回しかダウンロードできない**ので大事に保管）。Key ID を控える。
2. Firebase コンソール → ⚙ プロジェクトの設定 → **Cloud Messaging** → Apple アプリの構成 → **APNs 認証キー** をアップロード
   （Key ID と、チーム ID `5B2NQ74986` を入れる）。Cloud Messaging そのものは無料プラン（Spark）で使える。

## 5. 古いアプリを締め出す（全員が新しい版にしてから）

友達全員が新しい版（匿名ログインの入った版）にしたら、`firestore.rules` の

```
function allowsLegacyClients() {
  return true;
}
```

を `false` にして、もう一度 `firebase deploy --only firestore:rules`。
これで「URL と API キーさえ知っていれば誰でも読み書きできる」状態が終わる。
早すぎると、古い版の人だけ同期できなくなる（エラーにはならず、写真が届かなくなる）。全員の版は Analytics の「アプリのバージョン」で確かめられる。

**「自分が撮った写真も消す」と古い版**: 新しい版どうしなら、取り消した写真は戻らない。
ただし古い版（取り消しの印を知らない版）の端末が同期すると、その端末が持っていた写真をサーバーに書き戻してしまう。
抜けた人の端末が残っていれば、次の同期で取り消し直す。抜けたあとすぐにアプリを消した場合は直らない。
なので、**全員が新しい版にしてから**本格的に配る。もう1つ、写真の本体は Cloudinary に残る
（アプリからは消せない仕組みのため。URL はどこにも載らなくなるので、誰の画面にも出ない）。消したいと連絡が来たら、Cloudinary の管理画面で消す。

## 7. App Store Connect の申告

- **年齢区分の質問**: ユーザーが作った内容（写真）を見せ合う → 「ユーザー生成コンテンツ」は **はい**。
  メンバーどうしでやりとりする → 「メッセージ・チャット」は **はい**（作品のタイトルや写真が相手に届くため、安全側で）。
  「ソーシャルメディア」（知らない人とつながる）は **いいえ**（招待コードを知っている友達だけ）。
- **通報への対応**: 報告はコンソール → Firestore → `reports` に溜まる。審査では「報告に24時間以内に対応する」体制が求められる。
  対応は、写真の URL から Cloudinary の管理画面で写真を消す。
- **App Privacy**: `ANALYTICS_SETUP.md` 5章のとおり。今回増えたもの: 押し出し通知の宛先（端末のトークン）、匿名ログインの ID（どちらも「アプリの機能」のため、個人とは結びつけない）。
- **アカウント削除**: アカウント登録が無いので必須ではないが、「グループを抜ける → 自分が撮った写真も消す」でサーバーから自分の写真を取り消せる（ガイドライン 5.1.1(v) への答えとして、審査メモに書いておくとよい）。
