## 体験の中心

Rotash は「自分の担当日に写真を投稿するアプリ」ではありません。

> 参加者全員が同じ7分割キャンバスを毎日見ながら、
> 1週間かけて1つの写真作品を完成させるアプリ

- **撮れるのは1日に1人だけ**（全員が毎日投稿するのではない）
- **見るのは誰でも、いつでも全部**。曜日による閲覧制限は一切ない
  - 金曜担当者も、月〜木の写真をずっと見られる
  - 土曜担当者も、それまで完成した写真を見られる
- 3人なら 月A 火B 水C 木A 金B 土C 日A と一巡し続ける
- 7枚そろうと、その週の作品が完成する
- 端末を**横向き**にすると、7分割された「今週の作品」が現れる

全員が「観客」と「制作者」の両方になります。自分の担当日だけ作者になる。
「自分の番だから開く」だけでなく、「今日はどこまで完成したかな」で毎日開く体験を狙っています。

縦向きは Rotash の入口。表示するのは グループ名（押すと掛け持ちの切り替え）/ 招待コード / **撮られた写真の並び** / メンバー / Memories / 設定 だけです。
メンバーの丸は、その人が最後に撮った**裏の写真**（たいてい本人の顔）で、撮るたびに替わります。
横にした瞬間に「THIS WEEK」を見せたいので、**縦では今週の7分割は出しません**
（進捗バー的な埋まり具合表示も含めて）。完成した過去作品のプレビューだけは Memories に出ます。

**撮られた写真の並び**（`PhotoCarousel`、2026-10-15）: 真ん中に、**いちばん新しく撮られた1枚**を大きく置きます
（今日がまだ撮られていなければ、昨日やその前の1枚。今日の枠ではありません）。左には、それより前に撮られた写真が奥へ傾いてのぞきます。
右へすべらせると左の写真が真ん中に来て、真ん中だった写真は右へ下がります（右に見えるのは真ん中より新しい写真だけなので、はじめは何もありません）。
今週だけでなく、これまでの週の写真もさかのぼれます（今週ではない写真には日付も出します）。
写真には横の7分割と同じく**裏の丸**（もう一方のカメラ）を添え、**丸を押すか長押し**で裏返り、**押すと全画面**で大きく見られます（`PhotoViewer`。横の7分割と同じ画面）。
縦のホームはスクロールなしの**ちょうど1画面**で、ほかの部品を置いて余った高さをこの並びが全部使います（機種ごとに画面の高さが違っても、はみ出さない）。
1枚は横画面の1枠より太い縦長です（幅 : 高さ = 0.48 : 1）。左右の写真は、真ん中の大きさとは別に、細い帯（画面の幅の約9%）がのぞくだけにしています。圧が強くならないよう、写真には少し黒を重ねて抑え、左右の写真はさらに暗くしています。まだ1枚も撮られていないグループでは、代わりに今日の1マス（`TodayCard`）を出します。
「横にして見る」のような案内は出しません。出すのは、自分の番でまだ撮っていない日の「今日はあなたの番 ・ 横にして撮る」だけです。
撮るのは横だけです（Setlog の「横にするとカメラが出てくる」を元にした設計。縦で撮る試験は 2026-10-15 に外しました）。

**メンバー**: 写真の並びの上に横一列。最後に招待の丸（7人そろったら出さない）。収まらないときは横にすべらせます。

**Memories**: ホームには先週の（いちばん新しい）作品だけを、名前と日付・7枚の小さな写真で置きます。
「MEMORIES」を押すと、これまでの作品が全部並ぶ画面（`MemoriesView`）が開きます。作品は毎週増えていくので、
全部をホームに並べるとホームがどこまでも長くなるためです（2026-10-15。縦のホームを1画面に収める）。

**初めて入った直後**: 初めてグループを作った・入った直後は、縦に持っていても縦のホームではなく、
**横の作品画面をそのまま横に倒して**見せます（`RootView` の `WorkInPortrait`）。説明の文字を出さなくても、
横向きの画面が出ていれば人は自然とスマホを傾けます。傾けると本物の横画面になり、そのあと縦に戻すと、いつもの縦のホームになります。
倒す向きは、多くの人がスマホを左に倒して（反時計回りに）横にする向きに合わせています。倒して見せている間は押しても何も起きません。

**振る**: 横画面で端末を振ると、作品全体が一度に裏返ります（裏の写真が大きくなる）。もう一度振ると戻ります。

**Memories の画面**（`MemoriesView`）: いちばん新しい作品だけを大きく（7分割を横に並べて名前・日付つき）、それより前の週は少し小さく薄く、右に日付を添えて積み重ねます
（続いていることは数字ではなく厚みで見せる）。作品を開くと、上に作品全体（7分割）、下にその日の写真を大きく出します。
枠を押すとその日へ、下を左右にめくるととなりの日へ移ります。大きい写真の右下の丸を押すと、表と裏が入れ替わります。

**完成した週（横）**: 7分割の大きさと位置は進行中のときと変えません（撮った瞬間に画面が動かないように）。
完成したことは見出しの `COMPLETE` で伝え、週の名前も見出しに出します（名前をつけられるのは7枚目を撮った人だけ）。

## 動かし方

1. Xcode 16 以降で `Rotash.xcodeproj` を開く（iOS 17 以上、iPhone 向け。初回は Firebase の Swift Package の取得に少し時間がかかる）
2. `Rotash` ターゲットの Signing で自分の Team を選ぶ
   （`PRODUCT_BUNDLE_IDENTIFIER` は `app.takaoka.com.Rorash`。`Rotash/Services/GoogleService-Info.plist` の `BUNDLE_ID` と一致させること）
3. 実機を選んで Run（**カメラを使うので実機推奨**）

> `Rotash/` 配下は Xcode 16 のファイルシステム同期グループです。
> ファイルを増やしてもプロジェクトファイルを触る必要はありません。
> 古い Xcode で開けない場合は `xcodegen generate`（`project.yml` 同梱、XcodeGen 2.43.0 以降）でも生成できます。
> ただし正は `Rotash.xcodeproj` で、`project.yml` は手で同期している写しです。
> Xcode で設定やパッケージを変えたら `project.yml` にも反映し、生成後は `git diff Rotash.xcodeproj` を確認してください。

シミュレータではカメラが無いため、シャッターを押すとダミー画像が入ります。
7分割が埋まっていく流れだけは確認できます。

## 撮影のつくり

**通常のカメラ UI（全画面プレビュー＋確認画面）は作りません。**

- 画面には最初から 7分割レイアウトがある（他の枠の写真もそのまま見えている）
- 撮ると、その枠がそのまま写真で埋まる（確認画面なし）

**撮影権限**: その日の担当者だけが、その日の枠を撮影できる。
他の日の枠は見えるだけで撮れない（未来の枠も、他人の日も）。

**表と裏を同時に撮る**: シャッターを押すと、**大きい画面に映っている方（表）**と、
**シャッターの丸に映っている方（裏）**を同じ瞬間に撮ります（`CameraController.captureBoth`）。

- シャッターは、裏のカメラが中に映る丸いカメラです（`CameraShutter`）。最初は表が外カメ・裏が内カメで、
  `FLIP` で入れ替えます。表か裏かは、内カメ・外カメではなく「大きい画面側かシャッター側か」で決まります
- 前後のカメラを同時に動かせる端末（iPhone XS 以降。`AVCaptureMultiCamSession`）は完全に同時。
  それ以外の端末（一部の iPad）は、表を撮ったあとカメラを切り替えて裏を自動で続けて撮ります
- 7分割の枠は、表を大きく出し、**裏を枠の下に丸で添えます**。曜日と名前は枠の上に置き、写真の主役が来る真ん中を空けます。
  共有画像（ストーリー）も同じ並びです（`RotashFeatureFlags.shareShowsReverseBadge` を false にすると表だけ）。
  ストーリーは指で送られていくので、裏返る動きや2枚目を待ってもらえるとは限らず、1枚目で両方のカメラを見せるためです。
  枠を**長押し**（0.25秒）するか、**枠の下の丸を押す**と、その枠が裏返り、裏が大きく・表が丸になります（いつでも）。
  写真のある枠を**押すと全画面で大きく**見られます（右下の丸で表と裏が入れ替わる。背景か × で閉じる）。
  撮り直しは、撮った直後に下に出る RETAKE から行います。
  週が終わると、Memories で**作品ごと裏返せます**（左から1枚ずつ裏返る）
- 裏の写真は `Slot.reversePhotoFilename` / `reversePhotoURL` に持ち、表と同じように同期・手渡し・撮り直しされます。
  記録の無い古い写真には裏がありません

**撮る画面**: どちらの向きでも、**保存される写真の範囲を大きく映し、サムネ（7分割の枠）に入る範囲を線で示します**（`ThumbnailGuide`）。

- 横持ち（`ThisWeekView`）: はじめは**元の7分割のまま、今日の枠の中に**ライブビューを出します。
  **ピンチで横に広げたり縮めたり**でき、いちばん広いと7分割（月〜日）の横幅いっぱいになります（`liveScale`）。
  変わるのは見る範囲だけで、**保存する写真はいつもカメラの映像そのまま（4:3）**です。
  1枠より広げているときは、7分割のサムネに入る範囲を線で示します（`ThumbnailGuide.thumbnailRegion`）。
  写真（4:3）より横長に広げると上下が切れて少し寄って見えるので、線もそのぶん太くなります。
  ピンチをここで使うので、ズームは付けていません。外カメは超広角（0.5倍）、内カメはセンサーいっぱいの広さで撮ります。
  今日の枠の真ん中に重ね（端の曜日は内側に寄せる）、近くの日は広げている間だけ隠れます。画面をタップしても撮れます。
  裏（もう一方のカメラ）は、今日の枠の下（撮ったあと裏の丸が添えられる所）に同じ大きさの丸で映します
  （`ReverseLiveCircle`。押すと表と裏が入れ替わる）。広げても縮めても丸は変わりません。
  シャッターと FLIP は7分割の右端に縦に並べます（`ShutterButton`）
- 裏の丸は、撮るときも撮ったあと（枠の下・共有画像）も同じ大きさ（1枠の幅の 0.8 倍。`ReverseBadge`）で、
  中身は**裏の写真に入るいちばん大きな丸（直径＝写真の短い辺）を縮めたもの**です。黒い帯は出ません。
  裏の写真そのものは 4:3 のまま保存しているので、長押しで裏返せば全体が見られます
- 写真は加工せず、7分割では枠いっぱいに収めて（真ん中を切り出して）表示します

**超広角（外カメ）**: 外カメは iPhone 標準の 0.5倍（超広角）があればそちらを使います
（`CameraController.device(for:)`）。超広角の無い機種と内カメは普通の広角です。
`RotashFeatureFlags.prefersUltraWideBackCamera` を `false` にすると 1倍に戻ります。

**画角を広げる試み（やめたもの）**: 細い枠に広い範囲を入れるために、表示で写真を曲げる・縮めて上下を黒くする・
人を守って背景だけ押し込む（Vision）・シームカービング・パノラマ合成・内カメのいちばん広い読み出し・
Apple の歪み補正などを試しましたが、外カメの 0.5倍だけを残して取り外しました。
コードは Git の履歴に残っています（取り外す直前のコミットは `cdd66f8`）。

**撮り直し（実験中）**: **撮った直後の30秒だけ**、撮った本人が何度でも撮り直せます。
目ブレ・指かぶりなどの「事故」を救うためのもので、30秒では撮り比べるほど撮れないので、
残るのは「ベストショット」ではなく「その日の1枚」のままです。

- 起点は**その日の最初の1枚**。撮り直しても30秒は延びません（`Slot.capturedAt` は最初の時刻のまま、
  撮り直した回数は `Slot.retakeCount` に入る。1秒以内の撮り直しも見分けられるよう、時刻ではなく回数で比べる）
- 撮った直後は画面下に `RETAKE  24` のような残り秒数つきのボタンが出ます。押すと枠にライブビューが戻り、
  シャッターでそのまま上書き。時間が切れるとボタンもカメラも黙って消えます
- 秒数は `RotashFeatureFlags.retakeWindowSeconds`。**0 にすると撮り直しは完全に無効**（以前の仕様）
- 同期: 同じ人の同じ1枚どうしは「新しい版」を採ります（`RotashMerge.isSameShot`）。
  別の人の写真どうしは、これまでどおり先に撮った方が勝ちます。
  同期の最中に撮り直しても巻き戻らないようにしてあります（`AppViewModel.keepingPhotosTakenDuringSync`）
- 分析イベント `photo_retaken`（最初の1枚から何秒後か）で、事故の救済に使われているかを見ます

撮影回数の表示・フィルター・編集・AI加工はありません。
`RotashFeatureFlags.allowRetake` を `true` にすると、時間に関係なく撮り直せるようになります（検証用）。
撮影可否の判定は `AppViewModel.canShoot` の1箇所に集約しています。

写真は横長のまま保存します。縦への自動変換はしません。

**画面の見た目**: 7分割は常に同じ比率の7列です（`GeometryReader` で幅を明示計算）。
最初の1枚だけ大きく見える、というレイアウトにはしていません。
横画面の見出しには `THIS WEEK`・日付・`N / 7`（決着したら `COMPLETE`）・SHARE だけを置きます。
写真上の「TODAY」表記や、撮影中の「◯枚そろいました」といったテキストは出しません。
7枚が左から埋まっていく状態そのものと、各枠に出ている曜日・担当者名だけで十分伝わる、という考え方です。

## 共有

加工・テンプレート・装飾・選択肢は入れていません。**1タップで1枚**出ます。

`Services/WorkExporter.swift`。**1080 × 1920（9:16）** の縦1枚。

いまの標準（`RotashFeatureFlags.shareCardFormat = .story`）は、**7分割を「横帯 × 7」に組み直して縦に積んだもの**です
（2026-10-15 に切り替え）。写真がまっすぐ立ち、1枚あたりの写る量も多いので、ストーリーで首をかしげずに見られます
（dump と同じ見え方）。上から月曜→日曜の順です。

Instagram のストーリーでは、上（進み具合の線と名前）と下（返信の欄）に表示が重なります。
文字（`THIS WEEK`・日付・`N / 7`・週の名前・`ROTASH`）はどちらにも入らないよう、上下およそ 250px を避けて置いています。

各帯は、左下に曜日と今日までの担当者名、右に**裏（もう一方のカメラ）の丸**を置きます（`shareShowsReverseBadge`）。
帯の下に週の名前（ついていれば）と、`ROTASH` ＋ その週に1枚でも撮った人の名前を `|` で分けて添えます
（別の署名ブロックは付け足しません）。

| | アプリの1枠 | `.story` の1帯 |
|---|---|---|
| 形 | 246 × 784（1 : 3.2 の縦長） | 1032 × 179（5.8 : 1 の横長） |
| 4:3 を aspectFill | 高さを合わせて**左右を切る** | 幅を合わせて**上下を切る** |

もう1つの形 `.screen` は、横画面の7分割をそのまま組んで、中身ごと時計まわりに90度倒したものです。
受け取った人が端末を横にすればアプリと同じ並びが出てきますが、写真も文字も横向きのまま縦に並びます。
フラグを `.screen` に戻せば切り替わります。
**未来の担当者は共有画像にも出しません**（アプリの外から不確実性を壊さないため）。

完成していなくても書き出せます。0/7 は招待状、3/7 は途中経過、7/7 は作品で、
どれも同じ生成器から出る同じ形式の画像です。SHARE は横画面の見出しと、Memories の作品ページにあります。
共有するのは**画像1枚だけ**で、文章もリンクも付けません（`rotash://new` のリンクは、押せない文字列になるうえ AirDrop を共有先から消してしまうため）。

## 同期（Firestore + Cloudinary）

誰かが撮ったら、他のメンバーの端末にも届くようにしています。

- **状態**（メンバー・担当・週）は Firestore
- **写真の実体**は Cloudinary（Firebase Storage は無料枠だけで完結しないため）

どちらも無料枠のみで動きます。**`SyncConfig` が空のあいだはローカル保存のまま動く**ので、
未設定でもアプリは普通に使えます（その場合は設定の「バトン」が使えます）。
このリポジトリの `SyncConfig` には、作者の接続先がすでに入っています。

### Firebase SDK は同期には使っていない

Firebase の Swift Package（12.18.0）から、使う4つだけをリンクしています。

| 部品 | 使い道 |
|---|---|
| `FirebaseCore`・`FirebaseAnalytics` | 計測（`AnalyticsService`） |
| `FirebaseAuth` | 匿名ログイン（`AuthService`）。ID トークンを Firestore への REST の読み書きに添える。入れ直しても同じ uid なので「前の自分」に戻れる |
| `FirebaseMessaging` | 「◯◯が撮った」の押し出し通知の宛先（`PushService`。端末のトークンを `devices/{uid}` に置く） |

サーバー側は `firebase.json`・`firestore.rules`（ルール）と、「◯◯が撮った」の送り役 `tools/push-relay.gs`（Google Apps Script。無料）です。
コンソールでの有効化とデプロイの手順は [`docs/FIREBASE_SETUP.md`](docs/FIREBASE_SETUP.md)。

同期そのものは、Firestore を REST API で叩いて **URLSession だけで実装**しています。
そのかわりリアルタイム購読は使えないので、同期するのは次のタイミングです。

- アプリを開いた / 復帰したとき、開いたまま日付がかわったとき
- 横にしたとき（THIS WEEK を開いたとき）
- 写真を撮ったとき、週の名前をつけたとき、グループを切り替えたとき、参加・抜けたとき
- 縦画面で下に引っぱったとき、設定の「今すぐ」を押したとき

1日1枚ずつ撮る使い方では、これで十分間に合います。

### セットアップ

自分の接続先で動かすときは、`Rotash/Services/Sync/SyncConfig.swift` の4つの値を書き換えます。

1. **Firebase**: プロジェクトを作り Firestore を有効化 →
   プロジェクトの設定から `プロジェクト ID` と `ウェブ API キー` を転記
2. **Cloudinary**: アカウントを作り、Settings → Upload →
   **unsigned** の upload preset を作成 → `Cloud name` と preset 名を転記

この2つはどちらもクライアントに配る前提の値で、秘密鍵ではありません。
**Cloudinary の API Secret は絶対にアプリに入れないでください。**

> **セキュリティルールについて**（重要）
>
> Firestore をテストモードのままにすると、**URL を知っている誰でも
> 全グループのデータを読み書きできます**。自分の接続先で動かすときは、
> 最低限、招待コードを知らないと触れないようにするため、ドキュメント ID（= 招待コード）が
> 6文字であることを条件にするなどのルールを入れてください。
> ログイン（認証）を入れない限り、これは「鍵を知っている人だけ」以上にはなりません。
>
> このリポジトリには、作者の接続先に入れるルールを `firestore.rules` として置いてあります
> （一覧の読み取りは禁止・ログインしている人だけ読み書き・消せない）。反映のしかたは
> [`docs/FIREBASE_SETUP.md`](docs/FIREBASE_SETUP.md) 2。

### 突き合わせの考え方

サーバーには「グループの状態を JSON 文字列 1 個」として置いています。
既存の Codable モデルとマージ処理をそのまま使えるためです。

同期は毎回 **取得 → 突き合わせ → 書き戻し** で、
突き合わせは `Services/RotashMerge.swift`（副作用なしの純粋ロジック）。

- 片方にしか無い写真は必ず残す
- 同じ枠に両方あるときは **先に撮られた方** を採用
- 同じ週を別々に撮っていても合流する

同時に書き込むと後勝ちで一部が欠けることがありますが、
各端末のローカルには写真が残っているので、次の同期で自然に復旧します。

## バトン（同期を使わない受け渡し）

同期を設定していないときは、これまでどおりファイルで手渡しできます。

- 設定 → 「渡す」→ `.rotash` ファイルを AirDrop / LINE などで送る
- 受け取った人は 設定 → 「受け取る」から読み込む
- 同期と同じ突き合わせ処理を通るので、写真は消えずに合流します

## メンバーの増え方

つくる人は **自分の名前だけ** 入れます。メンバーを先に並べる画面はありません。

1. つくると招待コードが出る
2. INVITE（縦のホームの招待コード、またはメンバー列の「＋」）をタップすると、共有シートで
   **文章（招待コード入り）+ いまの作品の画像 + 招待リンク**が送れる。
   リンクはメッセージやメールのように文章を送る相手にだけ渡し、AirDrop や写真アプリには画像だけが渡る
3. 受け取った人がリンクを開くと、**コード入力を飛ばして名前だけ**でメンバーになる。
   コードの欄には「貼り付け」ボタンもあり、招待の文章をまるごとコピーしてきても、中のコードだけを拾う
4. 参加した人は、その週の残りの当番にも入る。**今日の1枚がまだ撮られていなければ、今日の番がその人に渡る**（途中参加の項を参照）
5. 1つのグループに入れるのは**7人まで**（`RotashGroup.capacity`。8人目は「このグループは7人でいっぱいです。」）

コードだけを LINE に貼ると、受け取った側に見えるのは意味不明な6文字で、
何のアプリかを招待した側が説明しなければなりません。画像を添えれば説明は要りません。
リンクが押せない相手でも手で入力して入れるよう、コードは文章の中にも入れてあります。
対面でそのまま伝えたいとき用に、コードのコピーも残してあります。

### リンク（`Services/RotashLink.swift`）

2種類あり、**意味がまったく違います**。

| | 用途 | 公開してよいか |
|---|---|---|
| `rotash://join/ABC123` | 自分のグループの空き枠に呼ぶ | **不可**。Story に貼ると他人が7枠に入れる |
| `rotash://new?from=<UUID>` | 公開した作品を見た人が、自分たちのグループを作る | 可 |

`new` に付く `from` は、**その作品から新しいグループがいくつ生まれたか**を
知るための唯一の手がかりです。受け取る側（`AppViewModel.handle`）は実装してありますが、
**いまはどの共有にもこのリンクを載せていません**（上の「共有」の理由）。
そのため、公開した作品から生まれたグループ（K）は、今のところ測れません。
**アプリが入っていない人**: 自前の招待ページは持ちません（置いておく負担が重いため）。
App Store に公開されると、招待の文章に **App Store のリンクが自動で付きます**（`AppStoreLink`。起動時に Apple の検索で確かめる）。
受け取った人はアプリを入れてから、招待の文章をコピーして参加画面の「貼り付け」を押せば入れます。

同期が未設定のときは、コードだけでは相手のグループを見つけられないので、
参加後にバトンを受け取ってもらう必要があります。

メンバーは**招待コードで本人が参加して増えるだけ**です（名前だけの人を設定で足す機能は外しました。
足しても撮る端末が無く、その人の当番の日がいつも No Shot になるため）。

### グループの掛け持ち

1台で複数のグループに入れます（`RotashLibrary`。端末には `groups.json` に全部を保存。
以前の `state.json`（グループ1つ）は初回に読み替えます）。

- 縦のホームのグループ名を押すと、切り替え・新しく作る・招待コードで参加 が出ます
- 同期は入っているグループを順に全部。朝の通知は1通にまとめ、各グループの今日の担当を1行ずつ並べます
- 横画面の見出しには、掛け持ちしているときだけグループ名が出ます

### 抜ける

設定の「このグループから抜ける」で、この端末からそのグループと写真を消します。抜けるときは2つから選べます。

- **抜ける（写真は友達の作品に残す）**: 自分が撮った写真は、ほかの人の作品にそのまま残る
- **抜けて、自分が撮った写真も消す**: サーバー上の自分の写真に「取り消した」印（`Slot.withdrawnAt`）を付け、
  名前も「—」にする。写真は「絶対に落とさない」ように同期しているので、ただ消すと古い端末が書き戻してしまう。
  印はどちらかが持っていれば必ず消す側に倒れる（`RotashMerge`）。取り消した枠は撮られなかった日（—）と同じに見える


同時に、サーバーの自分のメンバーに「抜けた」印（`Member.leftAt`）を付けて、ほかの人の端末で
**まだ来ていない日の当番から外れる**ようにします。印は同期の最後に送り、サーバーに載ったことを
次の同期で確かめるまで送り直します（`PendingLeave`）。メンバー一覧からは消さないので、過去の作品の名前は残ります。
入り直したときは、匿名ログインの uid が同じなら**前の自分として戻ります**（`RotashSyncService`。同じ名前の別人が増えない）。

### 報告・見えなくする（App Store ガイドライン 1.2）

写真を開いたときの「…」から、**報告する**（運営に届く。`reports` コレクション）と、
**この人の写真を見えなくする**（この端末だけ。ほかのメンバーには伝わらない）ができます。
縦のホームのメンバーの丸を長押ししても、見えなくする・戻すができます。見えなくした写真は、共有画像にも出しません。
連絡先メール（`SyncConfig.supportEmail`）を入れると、設定画面に連絡先が出ます。

## 言語

日本語・韓国語・英語に対応しています（端末の言語で切り替わり、それ以外の言語は英語）。
文字は `Resources/Localizable.xcstrings`、カメラなどの許可の説明は `Resources/InfoPlist.xcstrings` にあります。
コードの中の日本語の文字列がそのままキーです。THIS WEEK / SHARE / SHOOT などの英字のラベルは、どの言語でも英字のままです。

## 日本語入力について

入力欄では、入力中にテキストを書き換える処理を入れていません。
日本語入力は変換中の未確定文字列を扱うため、`onChange` で値を書き換えると
入力セッションが壊れ、サードパーティキーボード（Simeji など）では
画面が閉じるなどの不安定な動作につながります。
名前の長さを詰めるのは「つくる」「参加する」を押した確定時だけです。

招待コードの欄だけは英数字しか使わないので、
キーボードを ASCII に固定して日本語入力を経由させないようにしています。

また、シートの表示状態は View の `@State` ではなく `AppViewModel` に持たせています。
キーボードの都合で View が作り直されても、入力中の画面が閉じないようにするためです。

## 週の扱い

グループは毎週続きます。「新しい週を作る」操作はありません。

- カレンダー上の週は常に **月曜〜日曜**
- 月曜になったら自動的に次の週へ切り替わり、前の週はそのまま Memories へ
- THIS WEEK には常に今の週だけを表示

**週の途中で始めた場合**、その日から日曜までが初回の作品になります。
金曜に作れば FRI/SAT/SUN の 3 枚、水曜なら 5 枚。
翌月曜からは通常の 7 枚に戻ります。
「作った曜日が毎週の開始曜日になる」わけではなく、初回だけの特殊ケースです。

## 担当者の決め方

`Services/AssignmentPlanner.swift`。完全ランダムでも単純ローテーションでもなく、
**公平性を保証した上でランダム**に決めます。副作用の無い純粋ロジックです。

優先順位:

1. 累計担当回数の公平性
2. その週の担当回数をできるだけ均等に（2人=4/3、3人=3/2/2、4人=2/2/2/1 …）
3. 同じ人の 2 日連続を原則避ける
4. 前週とまったく同じ並びを避ける
5. 残った候補からランダム

条件を全部は満たせない場合（1人グループなど）でも、進行不能にならないよう
段階的に条件を緩めて必ず割り当てます。

ランダムは**種つき**（グループ・週・メンバーから決まる）なので、同じメンバー・同じ週なら
どの端末で計算しても同じ担当表になります。端末ごとに違う表ができると、同期が届くまで全員が
「今日は自分の番」に見えてしまうためです。同期のあとは `AssignmentAudit` が担当表を検査し、
食い違いがあれば直します（過ぎた日と今日の担当には触りません）。

## 担当者はその日まで公開しない

週の頭に全員分の担当を公開しません。**今日までの担当者だけ**が見えます。

- 過去の曜日: 写真 + 担当者名
- 今日: 担当者名 + 撮影状態
- 未来: 空白のみ（写真も担当者名も出さない）

「次に誰が撮るのか分からない」という不確実さ自体を体験として残すためで、
カレンダーやスケジュール表にはしません。

## 途中参加

新しいメンバーが週の途中で入っても、「翌週まで閲覧だけ」にはしません。
**その週から作品づくりに参加**します。

未来の担当者はそもそも誰にも公開していないので、内部で組み替えても
「予定が変更された」という見え方になりません。この性質を使っています。

- 過去の枠は **絶対に変更しない**（写真も担当者も）。今日の枠も、写真があれば変えない
- **例外: 入った日の今日の番**（#28・46、2026-10-15）。今日の1枚がまだ撮られていなければ、今日の番を**今日入った人に渡す**。
  入った直後に何もすることが無いと、入れたのかどうかも分からないまま閉じてしまうため（友達テストで実際に起きた）。
  同じ日に2人入ったら、先に入った人（`Member.joinedAt` がいちばん早い人）。あとから入った人が奪うことはない。
  決定時刻は入った時刻にするので、どの端末で計算しても同じ答えになる（`AssignmentAudit.handOverToday`）
- それ以外に変更するのは「今日より後の、まだ公開していない枠」だけ
- 「最初の枠を無条件で渡す」ことはしない（同じ日に二人が入ると、先に入った人の当番が消えるため）。
  そのかわり、累計の担当回数が少ない人が優先されるので、累計 0 回の新しい人は、
  放っておいても最初の空き日に入りやすい（木曜参加なら、たいてい金曜担当）
- 今日より後の日は、その人を含めた全員で通常の公平性ルールに従って再配置
- 翌月曜からは、他のメンバーとまったく同じ条件でローテーションに入る

ユーザーから見ると、金曜になって初めて「今日は D なんだ」と分かるだけで、
内部で再計算されたことは一切表示されません。

## No Shot（写真がなかった日）

担当者がその日に撮らなかった場合、**担当を変更したり代理を立てたりはしません**。
その日は「写真がなかった日」として作品にそのまま残ります。

- assignment は変更しない。その週の残りの担当もそのまま
- 「休み」「欠席」「代理」といった管理アプリ的な表現はしない
- 表示は `—` だけ。写真がないこと自体をエラー扱いしない

枠の状態（写真 / No Shot / 今日 / これから）は保存せず、
**写真の有無と日付から導出**しています（`RotashWeek.state(of:)`）。
状態遷移の処理を持たずに済み、過去の週でも常に正しくなるためです。

### 7枚そろわなくても作品は成立する

`isComplete`（全部写真）とは別に `isFinished`（全枠が決着 = 写真か No Shot）を用意し、
**共有できるかどうかは `isFinished` で判断**します。
`— 📷 📷 📷 📷 📷 📷` のような作品も、そのまま Share / Memories で扱えます。
No Shot の日は、THIS WEEK・Memories・共有画像のどれでも、その位置に `—` だけが残ります。

## 撮影できる条件

- 撮れるのは **自分の当番日の当日だけ**
  （未来は撮れない。過ぎた日も No Shot として確定するので後から埋められない）

過ぎた日を後から撮れるようにしたい場合は、
`App/FeatureFlags.swift` の `allowCatchUpShooting` を `true` にしてください。

## 通知

`Services/NotificationScheduler.swift`。下の3種類は**ローカル通知**で、サーバーも APNs も使いません。
担当は週の開始時点で内部的に決まっているので、その週の分をまとめて予約するだけで足ります。

これとは別に、**「◯◯が今日の1枚を撮りました」の押し出し通知**を、撮った人以外のメンバーに1通だけ送る仕組みを作ってあります
（`PushService`・`PushRelay`）。送り役は Google Apps Script（`tools/push-relay.gs`。無料）で、置き方は [`docs/PUSH_RELAY_SETUP.md`](docs/PUSH_RELAY_SETUP.md)。
置くまで（`SyncConfig.pushRelayURL` が空のあいだ）は届きません。

送るのは3種類、どの端末にも **1日2通まで**。

| いつ | 内容 | 宛先 |
|---|---|---|
| 朝 8:00 | 「今日は MINA」 | 全員 |
| 夜 21:00 | 「今日はあなたの番です。まだ撮れます」 | **その日の担当の本人だけ**。まだ撮っていないときだけ |
| 日曜 21:00 | 「今週の Rotash」 | 全員（まだ撮っていない日曜の担当には、夜の1通だけ） |

夜の1通は、友達テストで「朝の通知に気づかず撮り忘れた」という声があって足しました（#21）。
撮ると予約を組み直すので、撮ればその日の分は消えます。1日1回きりで、重ねて催促はしません。
掛け持ちしていて同じ夜に番が重なったときは、グループ名を並べた1通にします。

朝8時に全員へ同時に出すのは、「Rotash の1日は朝8時に始まる」という
**共有された時刻**を作るためです。撮影は非同期でよいが、朝の合図だけは揃えたい。

担当が変わりうる操作（作成・参加・途中参加・週送り・同期）はすべて `persist()` を
通るので、そこで毎回まとめて組み直します。差分で消そうとすると、
消し忘れた古い名前がそのまま朝に届きます。

**入れないもの**: 催促の繰り返し / 進捗の煽り（「あと2枚！」）/
「3日間開いていません」。通知が「友達について」ではなく「アプリについて」に
なった時点で、Rotash は毎朝の楽しみではなく義務になります。

「7枚目が入った瞬間」を全員に届けるにはプッシュが要るので、そこはまだです。

## 週のタイトル

7枚が決着すると、**7枚目を撮った本人だけ**が一行のタイトルを付けられます
（20文字まで・あとから編集しない・空でも成立）。

曜日も日付も担当者名もシステムが出したものなので、**ここだけが人の言葉**になります。
共有画像に載る唯一の人間の声で、これが無いとどれだけ作り込んでも
自動生成された広告に見えます。同時に、アプリの中で唯一の「撮る以外の能動的な行為」でもあります。

全員が書けるようにすると、それはタイトルではなく**コメント欄**になります。
書けるのは常にひとりだけにしてあります。
